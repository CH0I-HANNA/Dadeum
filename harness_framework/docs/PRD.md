# PRD: 다듬 (Dadeum)

## 목표

PPT/PDF를 업로드하면 발표자료 전체를 하나의 집합으로 분석하여 디자인 일관성 점수, 이상 슬라이드, 원인, 수정안을 한 번에 제공하는 AI 기반 발표자료 리뷰 시스템.

---

## 사용자

| 페르소나 | 상황 | 핵심 니즈 |
|----------|------|-----------|
| 취업 준비생 | 포트폴리오/자기소개 PPT 마감 전날 | 어떤 슬라이드가 이상한지 빠르게 파악 |
| 대학생 | 팀플 발표자료 합치기 후 검수 | 각자 만든 슬라이드의 통일감 확인 |
| 스타트업 | IR Deck 투자자 발표 전 | 브랜드 일관성 + 전문성 점검 |

---

## 핵심 기능 (MVP)

1. **파일 업로드 및 분석 시작**: PPTX, PDF를 드래그 앤 드롭 또는 파일 선택으로 업로드. 업로드 완료 즉시 분석이 자동 시작되며 (별도 버튼 없음), 결과 대기 페이지로 자동 이동한다. 최대 50MB, 최대 50 슬라이드.
2. **Consistency Score**: 발표 전체의 디자인 일관성 점수 (0~100), 폰트/색상/레이아웃/콘텐츠 밀도 세부 점수 포함
3. **Outlier Slide Detection**: 전체 대비 튀는 슬라이드 자동 탐지, 이상 슬라이드 목록 + 이상 점수 표시
4. **Root Cause Analysis**: 각 이상 슬라이드의 원인 feature 설명 ("폰트 불일치", "색상 불일치", "과도한 텍스트 밀도" 등)
5. **Recommendation Engine**: 이상 슬라이드별 수정안 + 수정 후 예상 점수(Impact Score) 제공

---

## 파일 제약 조건

| 항목 | 제한 | 초과 시 동작 |
|------|------|-------------|
| 파일 형식 | .pptx, .pdf 만 허용 | 업로드 즉시 거부, 에러 메시지 표시 |
| 파일 크기 | 최대 50MB | 업로드 즉시 거부 (413) |
| 슬라이드 수 (최대) | 최대 50장 | 업로드는 허용, 51장째부터 무시하고 분석 진행 + 사용자에게 경고 표시 |
| 슬라이드 수 (최소) | 최소 3장 | 업로드는 허용, Outlier Detection 불가 안내 + Consistency Score만 제공 |
| 암호화된 파일 | 허용 안 함 | 파싱 실패 시 에러 메시지 "암호로 보호된 파일은 지원하지 않습니다" |

---

## 파일 엣지 케이스 정의

| 케이스 | 예상 동작 |
|--------|----------|
| 슬라이드가 모두 빈 슬라이드 | 분석 진행, 모든 feature가 0 → Consistency Score 100 (모두 동일), Outlier 없음으로 표시 |
| 슬라이드의 모든 텍스트가 이미지 안에 있음 (스캔 PDF 등) | Typography feature는 0으로 처리, 색상/레이아웃 분석만 제공. 결과 상단에 "텍스트를 추출할 수 없는 슬라이드가 포함되어 있습니다" 경고 표시 |
| 한 슬라이드에 텍스트 요소 없이 이미지만 존재 | 해당 슬라이드의 Typography feature는 전체 평균값으로 impute, 이미지/레이아웃 분석만 진행 |
| PPTX에 포함된 폰트를 서버가 갖고 있지 않음 | 폰트 이름은 python-pptx가 메타데이터에서 읽으므로 렌더링 불필요. 정상 처리. |
| PPTX에 애니메이션/전환효과 포함 | 무시하고 정적 상태(첫 번째 프레임)로 분석 |
| PPTX에 매크로 포함 (.pptm) | 거부. ".pptm 파일은 지원하지 않습니다. .pptx로 저장 후 업로드해주세요" |
| PDF가 이미지 기반 스캔본 | 텍스트 추출 불가. 색상/레이아웃만 분석 + 경고 표시 |
| 파일이 손상된 경우 (corrupted) | 파싱 단계에서 실패 → task status "error" + "파일을 읽을 수 없습니다. 파일이 손상되었거나 지원하지 않는 형식입니다" |
| 동일 파일을 연속으로 업로드 | 별개의 file_id를 발급하여 독립적으로 처리. 중복 체크 없음 (MVP) |

## 에러 상태 및 사용자 경험

### 업로드 단계 에러

| 에러 | 사용자에게 표시할 메시지 |
|------|------------------------|
| 지원하지 않는 파일 형식 | "PPTX 또는 PDF 파일만 업로드할 수 있습니다." |
| 파일 크기 초과 | "파일 크기가 50MB를 초과합니다. 더 작은 파일을 업로드해주세요." |
| 네트워크 오류 (업로드 중단) | "업로드 중 오류가 발생했습니다. 다시 시도해주세요." |
| 서버 오류 (500) | "서버에 문제가 발생했습니다. 잠시 후 다시 시도해주세요." |

### 분석 단계 에러

| 에러 | 사용자에게 표시할 메시지 |
|------|------------------------|
| 파일 파싱 실패 (손상/암호화) | "파일을 분석할 수 없습니다. 파일이 손상되었거나 암호로 보호되어 있습니다." |
| 분석 타임아웃 (120초 초과) | "분석 시간이 초과되었습니다. 슬라이드 수를 줄이거나 파일 크기를 줄여 다시 시도해주세요." |
| 서버 내부 에러 | "분석 중 오류가 발생했습니다. 다시 시도해주세요." + "다시 분석하기" 버튼 |

### 분석 단계 경고 (에러 아님 — task status = "completed"로 처리)

| 케이스 | 동작 | 사용자에게 표시할 메시지 |
|--------|------|------------------------|
| 슬라이드 수 부족 (3장 미만) | `task.status = "completed"`, `outlier_slides = []` 반환. Consistency Score는 정상 제공. | 결과 페이지 상단에 "슬라이드가 3장 미만이어서 이상 슬라이드 탐지를 수행하지 않았습니다." 경고 배너 표시. 프론트엔드는 `slide_count < 3` 으로 판별. |

### 분석 대기 중 동작

- 분석 상태는 1.5초 간격으로 폴링
- 120초 이상 polling해도 completed가 안 되면 클라이언트에서 타임아웃 처리 + "다시 분석하기" 버튼 표시
- 사용자가 결과 페이지에서 벗어났다 돌아와도 URL의 task_id로 결과 재조회 가능
- **단, 서버 재시작 이후에는 task 결과가 소멸하므로 task_id로 조회 시 404가 반환됨.** 404 수신 시 "분석 결과를 찾을 수 없습니다. 파일을 다시 업로드해주세요." 메시지 + 업로드 페이지 이동 버튼을 표시한다.

## 데이터 보관 정책

- 업로드된 파일: 분석 완료 후 1시간 뒤 서버에서 자동 삭제 (MVP는 수동 삭제 또는 재시작 시 삭제)
- 분석 결과: in-memory 저장 (서버 재시작 시 소멸). 결과를 다시 보려면 재업로드 필요. 결과 화면에서 이 사실을 사용자에게 안내.
- 개인정보: 파일 내용을 서버에 영구 저장하지 않음. MVP에서는 이 사실을 업로드 화면에 1줄로 명시.

---

## 동시 처리 제한

- MVP: 동시 분석 작업 제한 없음 (단, 서버 자원 부족 시 503 반환)
- 요청 제한(Rate Limit): IP당 분당 10회 업로드 (MVP는 구현 생략, 명시만)

- AI Auto-Fix (원클릭 자동 수정): V3에서 구현

- 분석 결과 영구 저장 및 히스토리
